## Stage-owner finding

The task's selector — "every stage in the contract whose owner is a role rather than the host" —
selects nothing. `core/src/stages/contract.ts` records `owner: "host"` on all five stages, because
the host drives every one of them. Taken literally the leg would have been vacuously green, which is
the failure `_driving.ts` warns about by name.

The selector the test uses instead is the phase-level owner: each stage's `producer` is resolved to
its shipped recipe, and every `kind: "agent"` phase's `owner` is a role whose prompt is composed and
scanned. That resolves to `architecture-reviewer`, `builder`, `designer` and `planner` across the two
task-granularity stages; the three command-granularity stages send no prompt and contribute nothing.
The first test asserts the role set is non-empty and that every composed source carries bytes, so the
leg cannot silently return to being vacuous.

Validation: `npm run test:unit` passed 1439/1439 tests in 271.2 seconds; `npm run typecheck` and
`npm run lint` exited 0.
