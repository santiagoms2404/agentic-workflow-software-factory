## Which gates the fence covers, and how it finds them

The gates are discovered, never listed: `STAGES` → each stage's `producer` → the shipped recipe of
that id → its phases → their `gates[]`. That resolves to five, all on `design-to-plan` —
`design_evidence_present`, `spine_declared`, `architecture_verdict_consistent`,
`architecture_review_clear`, `spine_carried`. `plan-build-test` declares none, and the three
command-granularity stages contribute none. Each gate is then bound to its `run` node in the recipe
SOURCE, and every AST lookup on that path asserts rather than skips: a gate the value declares and
the AST cannot find fails loudly, because silently shrinking a fence is how it goes green while
catching nothing.

## Q8's scope, and why the walk is closure-scoped

The fence covers those five and no others, per Q8. `git-diff.ts` compares a producer's claims against
the worktree the host observed, `command-evidence.ts` windows the output of a command the host ran,
and `contract-digest.ts` reads the repository outright — observing the repository IS their evidence,
so a fence over `GATE_IDS` would go red on its first run for a reason that is not a defect.

The walk starts at the `run` property rather than at the file, for a related reason: the recipe file
that declares these gates also calls `loadUserPrompt` at module scope, which reads a prompt off disk
before any gate object exists. "Does the file import `fs`" would answer yes, and for the wrong
thing.

The negative leg checks three shapes over the closure's transitive declaration reach — a symbol
declared inside `declare module "fs"` (which catches renamed and namespace imports),
`require`/`import()` with an fs specifier, and a whole-name backstop for a hand-rolled wrapper. The
positive leg is the other half: `run` takes at most one parameter, every read of it is `.envelope`
or `.previousEnvelope`, and passing the whole context on, a computed key, and an array pattern are
each refused — a callee holding the context would hold `worktree`, one property access from a path.
Across the same reach, no `process`, `globalThis`, `__dirname`, `require` or `import.meta`. A
companion test checks the two allowlisted names against the real `PhaseGateContext` members, so a
typo cannot widen the allowlist without saying so.

## All three shapes were seen to bite

A two-hop read — a same-module helper calling `readFileSync`, which is the shape a direct scan of
the closure misses — failed with both matchers naming the hop that reached it:

```
core/src/workflow/recipes/design-to-plan.ts:18 (node-fs-binding) readFileSync from "fs"
    via gate spine_declared -> core/src/workflow/recipes/design-to-plan.ts:17 recordedRequest
core/src/workflow/recipes/design-to-plan.ts:18 (read-file) readFileSync
    via gate spine_declared -> core/src/workflow/recipes/design-to-plan.ts:17 recordedRequest
```

Replacing one gate's input with `context.worktree` failed the positive leg with:

```
core/src/workflow/recipes/design-to-plan.ts:58 spine_declared reads context.worktree
```

Replacing it with `process.cwd()` — the ambient value wearing different clothes — failed with:

```
core/src/workflow/recipes/design-to-plan.ts:58 (process-global) process
    via gate spine_declared
```

Each was reverted and the file returned to 13/13.

## What a green result here does not mean

Stated in the test header as well as here, because it is the claim most likely to be over-read: this
proves a gate does not READ a document. It does not prove the document is irrelevant to whoever
WROTE the gate. Someone can read a cookbook, transcribe its rule into a comparison over envelope
fields, and pass here — correctly, because the gate that then runs depends on the envelope and on
nothing else. No test reaches the author's desk. What this removes is the runtime dependency: a gate
whose verdict changes when a file changes.

One cost worth naming for whoever runs the suite next. The first test in this leg pays roughly 44
seconds building a TypeScript program with a checker, and `quota-fence.test.ts` builds its own in a
separate process, so the unit suite now pays that cost twice. A shared helper would fix it and was
left alone as outside this task.

Validation: `npm run test:unit` passed 1449/1449 tests in 283.6 seconds; `npm run typecheck` and
`npm run lint` exited 0.
