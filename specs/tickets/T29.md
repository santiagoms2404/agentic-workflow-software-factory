outcome: A ticket that fixes a bug carries a check that fails on the base and
  passes on the candidate, and the host runs both.
context:
  - "Source: Q113 of specs/brainstorms/2026-11-24-design-contract.md, and Q123
    of specs/brainstorms/2026-11-25-hardening.md."
  - No gate in core/src/gates runs a reproducing check on the base. Of the
    October review's 503 bugs, 500 had a mechanical check that would have
    refused them.
acceptance:
  - "A light or plan ticket may declare the proof of a fix: a test file and the
    test names in it. The contract, the store, the parser, intake and the
    agreement module know the field, and a ticket without it behaves as today."
  - "When a ticket declares it, a host gate takes the candidate's version of
    that test file, lays it over the base in a scratch worktree and runs only
    those names: they must fail there by assertion, and pass on the candidate. A
    missing name, a crash, a timeout or a pass on the base is a refusal with its
    own message."
  - The gate reserves no call and runs before review. Its two results are
    journaled and shown to the reviewer and at the landing.
  - "A fixture run shows each outcome: proved, passes on base, crashes on base,
    name missing, fails on candidate."
  - Each refusal that can stop a run before spend is a trap at the next free id.
    The others are catalogued as after spend.
  - npm run test:unit, test:contract, test:sim, test:journeys, test:traps,
    typecheck and lint exit 0, each run alone.

    core/src/state/**, core/src/policy/**, core/src/observability/migrations/**,
