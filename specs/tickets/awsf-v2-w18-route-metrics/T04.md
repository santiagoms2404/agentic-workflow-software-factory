## What this ticket is

An **implementation** ticket. It moves the prototype's statistics into one pure module under `dashboard/shared/`, which core and the tab both import. No DOM, no fetch, no Node API.

The shared conventions (execution, the write boundary, the owner gates, the never-do list)
are in [`./README.md`](./README.md) and Section A of the build prompts, and apply unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there at landing, from the findings earlier tickets return in their envelopes. It holds
no placeholder because a shift hands that section to the builder after the prompt as text that
wins over it. It sits above the prompt because the sync fence compares everything after the prompt
heading with Section B byte for byte.

## Handoff

### 2026-09-28 — from T01 and T02

**C1. Route keys are not canonical.** `route_model` holds the adapter's form (`opus`) on
journal-derived phases and the configured selector (`claude:opus`) on config-derived ones, and
`route_provider` is NULL on config-derived rows for the Claude adapter, which declares no provider.
`RoleRow.route` carries the raw columns, and `routeMixed` is set when a role's phases differ on any
of them. Before grouping rows by route, normalise the key, or legacy and new runs of one route
will split.

**C2. `firstPass` and `blockedHere` can both be true.** A builder whose own phases all SUCCEEDED
with no correction is first pass even when its host tests phase then blocked the run with
`CommandPhaseFailure`, which counts as blocked here (model). Decide whether yield statistics
exclude blocked-here rows, and state it.

### 2026-09-28 — from T03 (delivered as `b8402fc`)

**C3. `blockedHere` already includes the owner's override.** `buildRoleRows` applies
`effectiveAttribution(run, run.ownerAttribution)`, so read `blockedHere` directly for the "not
blocked here" frontier axis and the blocked-here stat, and do not recompute it. Each row also
carries `attribution` (the value in force), `attributionSource` (`owner` or `heuristic`, `null`
unless the run is BLOCKED) and `heuristicAttribution`. The override's reason and date are on
`RunFacts.ownerAttribution`, not on the row.

**C4. The cause vocabulary moved to a contract.** `ATTRIBUTIONS` in `core/src/metrics/attribution.ts`
is now `ATTRIBUTION_CAUSES` from `core/src/contracts/attribution-record.ts`. `dashboard/shared`
must not import from `core/`: take the vocabulary as an argument or restate it with a parity
test. C1 and C2 are unchanged; the M1 journey did not trip them because no run blocks in a host
tests phase after a successful build.
