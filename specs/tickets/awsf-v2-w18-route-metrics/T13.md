## What this ticket is

An **implementation** ticket: the owner act that creates a replay, and the tagging that keeps replays apart from production in the rows, the API, the CLI and the rail. It builds `awsf prove` unregistered: the owner wires it with its guard verb after M4 lands (gate G18-B).

The shared conventions (execution, the write boundary, the owner gates, the never-do list)
are in [`./README.md`](./README.md) and Section A of the build prompts, and apply unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there at landing, from the findings earlier tickets return in their envelopes. It holds
no placeholder because a shift hands that section to the builder after the prompt as text that
wins over it. It sits above the prompt because the sync fence compares everything after the prompt
heading with Section B byte for byte.

## Handoff

### 2026-09-28 — from T05 (delivered as `6533c98`)

**C1. The evidence source is already derived.** `evidenceSource(row)` in
`dashboard/shared/route-metrics.ts` reads `workflow === "prove"`, and `recommend` and the lens
facet use it. A `source` field on `RoleRow` duplicates it; if you add one, keep it equal to
`evidenceSource`.

**C2. Two files pin the row and run shapes.** `MetricsRoleRow` and `MetricsRun` in
`dashboard/shared/types.ts`, and `RoleRowSchema` and `MetricsRunSchema` in
`core/test/unit/_metrics-schemas.ts` (`additionalProperties: false`). A new field on `RoleRow`
(source, item, arm, repetition, order) or a replay record on the run must be added to both, or
`api/metrics-route.test.ts` fails.

**C3. `stats` does not filter by source.** The production default must be applied before
`stats` is called, through the lens's evidence-source facet, not inside the module.

### 2026-09-28 — from T06 (delivered as `fcece03`)

**C4. The proving-ground path already exists.** `awsf metrics` defaults `--source` to `production`
and filters runs and rows through `evidenceSource`. `--source proving-ground` prints the same
role × route table over replay rows. Add the per-item, per-arm scores to `metricsReadout` in
`core/src/cli/commands/metrics.ts`. No new command is needed.

**C5. `MetricsRun` gained three attribution fields** (T07 C5). A replay record on the run joins
them in `types.ts` and `MetricsRunSchema`; C2 still holds.

**C6. `--json` refuses every filter, `--source` included.** The payload stays unfiltered, and
replay rows sit in it with `workflow: "prove"`.

### 2026-09-28 — from T10 (delivered as `9eca4c7`)

**C7. The proving-ground pill changes in two lines.** `sourcePills` in `dashboard/src/routes/metrics.vue`
sets `live: value === "production"` and `selected: value === "production" && …`. Turning the pill live
means changing both and dropping its title "M4 adds controlled replays". It already carries
`aria-pressed`, which `dashboard-metrics-a11y.test.ts` requires of every toggle pill.

**C8. The static scans find new files by name.** Any `dashboard/src/metrics-*.ts`, `Metrics*.vue`,
`routes/metrics.vue` or `metrics.css` change must pass the same checks: every token resolves in all
13 palette and mode pairs, no literal colour, no `$` amount except from `formatListEquivalent` (and
task 8's `formatRate`), every button and link is named, toggles carry `aria-pressed`, and any new
transition or hover lift has a reduced-motion stop. The helpers are in
`core/test/unit/_metrics-static.ts`. A new action pill, such as one that copies an `awsf prove`
command, joins `ACTION_PILLS` in the accessibility test.

**C9. The label walk renders every payload run and role-row.** Replay rows added to the fixture
through `synthetic-payload.ts` (T07 C4) are walked with no test edit. A per-arm score or an arm
label printed with a bare `$` amount fails `dashboard-metrics-labels.test.ts`.
