READ FIRST
  specs/awsf-v2-w18-route-metrics.html - task 19, and the 2026-09-30 Amendment
  dashboard/src/canvas-graph.ts - buildCanvasGraph: node kinds, edges, clusters, unplaced
  dashboard/src/canvas-layout.ts and dashboard/src/components/CanvasMap.vue - the simulation,
    clusterBox, the dot classes and the hover label
  core/src/api/routes.ts - card(), which builds each SessionCard GET /api/v1/sessions returns
  dashboard/shared/types.ts - SessionCard
  core/src/metrics/role-rows.ts - replays(), the read of the projected replay record
  dashboard/src/metrics-lens.ts - the #/metrics hash and its proving-ground source facet

WHY
  A replay carries no driving session and no plan, so the canvas draws each one as a loose run
  dot, and the 40 replays of a D3 round read as 40 unrelated runs. Each replay's record already
  says how they relate: its item, repetition, arm and order, projected as one replay events row
  per session (task 13). The scorer groups replays by item and repetition at read time. The
  canvas should draw the same grouping, from the same record, and store nothing.

DO
  Give SessionCard a replay field: { itemId, arm, repetition, order } or null. card() reads it
    from the session's replay events row, read-only. A payload that fails assertReplayRecord
    reads as null, as role-rows.ts does. Every fixture that builds a SessionCard gains
    replay: null.
  In buildCanvasGraph, add two node kinds. One proving-ground node per project that has a
    replay, labelled with its replay and pair counts. One pair node per (project, item,
    repetition), labelled "<item> · rep <n>". Each replay's run node gets one edge to its pair
    node, and each pair node one edge to its project's proving-ground node, as a new edge kind.
    A deck whose attempts are all one replay has one such edge. Weights count runs, as today.
  Add one cluster per project, keyed proving-ground:<project>, whose region encloses its
    proving-ground node, its pair nodes and their run nodes, so a round reads as one formation
    of pair groups.
  Keep the layout deterministic: the same projection settles to the same positions on every
    load, and every replay run settles nearer its own pair node than any other pair node.
  In CanvasMap, draw the two new kinds with their own dot classes from existing tokens, in all
    seven palettes and both modes. A replay run's hover label adds "<item> · rep <n> · <arm> ·
    place <order>". The proving-ground node opens #/metrics with the proving-ground source on,
    through metrics-lens.ts's own encoding. A pair node opens nothing.
  Rounds, suites and task-id prefixes are not recorded, so they draw nothing: all of a
    project's replays share one region, and a pair holds one run per arm replayed on it.

DO NOT
  Group by a task id's prefix, or infer anything else from the shape of a name.
  Add a field to the replay record, change awsf prove or the projector, write SQLite, or add a
    migration.
  Move anything that is not a replay: a projection with no replay builds a byte-identical graph.
  Add a dependency or a dashboard write. Draw with the existing SVG and tokens.
  Change the sessions board. It is out of scope.

BUILDER READY
  Graph tests on a synthetic projection of two items at two repetitions on four arms: one
    proving-ground node, four pair nodes, sixteen run-to-pair edges, four pair-to-hub edges and
    one cluster enclosing all of them. A projection with no replay builds the same graph as
    before, byte for byte. A malformed replay payload reads as null and draws a plain run. Two
    projects draw two regions.
  API test: GET /api/v1/sessions returns the replay field for a replay session and null for
    every other session.
  Layout test: positions are deterministic, and each replay run is nearer its own pair node than
    any other.
  A headless capture of the canvas on the synthetic projection, dark and light, returned in the
    envelope (manual: in the session report).
  npm run test:unit, npm run typecheck, npm run lint and npm run dash:build pass.

  proving-ground formation, one group per item and repetition, each holding one run per arm
  replayed. Hover a run for its item, repetition, arm and place. Click the proving-ground node
  and land on the metrics tab with the proving-ground source on.
