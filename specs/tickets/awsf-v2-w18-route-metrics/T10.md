## What this ticket is

The milestone's **testing ticket**. It proves what can be proven inside the builder's sandbox (tokens in all seven palettes and both modes, labels, placement, accessibility) and returns the visual record the owner's Chrome comparison works from. The sandbox renders no browser, so the capture comparison is owner acceptance.

The shared conventions (execution, the write boundary, the owner gates, the never-do list)
are in [`./README.md`](./README.md) and Section A of the build prompts, and apply unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there at landing, from the findings earlier tickets return in their envelopes. It holds
no placeholder because a shift hands that section to the builder after the prompt as text that
wins over it. It sits above the prompt because the sync fence compares everything after the prompt
heading with Section B byte for byte.

## Handoff

### 2026-09-28 — from T07 (delivered as `5f93651`)

**C1. Where the metrics styles are.** `dashboard/src/styles/metrics.css` (new, imported by
`main.ts`), plus `.card-controls`, `.metrics-control` and `.session-filter-label` in `dashboard.css`
and `.metrics-control` in `morphism.css`'s raised-control lists. Role dots take the config's
`agents[].color` inline through `readRoleColors`; no metrics file holds a literal hex colour.

**C2. The run-card check exists.** `dashboard-metrics-lens.test.ts` already asserts the control
follows the card's `</a>`, precedes the archive control, and carries the href, the accessible name
and the lucide import. Extend or reuse it rather than writing a second parser.

**C3. The only `$` the tab renders comes from `formatListEquivalent`.** The fourth summary label is
"List equivalent per landed run" for that reason. T07 C4's rate-card strings are not rendered yet.

**C4. The fixture is generated.** `core/test/fixtures/metrics/synthetic-payload.ts` writes
`payload.json` from the payload builder, and the lens test fails when they drift. Add runs there and
regenerate, never by hand.

**C5. Reduced motion.** `metrics.css` turns off the pills' transition and lift under
`prefers-reduced-motion`. The card controls' opacity fade comes from `dashboard.css` and has no such
rule yet.

### 2026-09-28 — from T08 (delivered as `689b474`)

**C6. Two `$` sources are not list equivalents, by design.** The Matrix row's "$in / $out" is the
rate card's per-1M price from `formatRate` in `dashboard/src/metrics-matrix.ts`, which task 8
requires, and an untested row repeats the payload's `prior` string (`UNTESTED_ROUTES` in
`dashboard/shared/benchmark-priors.ts`, e.g. "$2 / $10"). The static `$` test must exempt those two
by name; this contradicts C3's "the only `$`", and task 8's row wins. Every other `$` goes through
`formatListEquivalent`: tile prices, the Frontier's tooltip and card values (`formatX`). Log ticks
print no unit.

**C7. Static checks exist; extend them.** `dashboard-metrics-views.test.ts` lists the view files
(`VIEW_FILES`) and asserts no fetch or storage, no literal hex colour, imports only relative, `vue`
or `lucide-vue-next`, and no `wilson`, `stats` or `depth` in the two components. Add
`metrics-ledger.ts` and `metrics-run.ts` to that list rather than writing a second scanner.

**C8. Frontier marks are not buttons.** Each mark is a focusable `<g role="img" tabindex="0">` with
an `aria-label` that repeats its tooltip; it does nothing on click. Treat it as a non-control in the
"every control is a button or link" check, or decide to make it one. Matrix tiles with rows are
buttons named by `tileLabel`; empty cells are not controls. Reduced motion stops the tile lift and
the mark scale.

**C9. What the journey will see on the owner's data.** The builder Frontier has no Pareto line: 32
builder rows are route-attributed and kept out (INV-3), leaving two hollow routes. The reviewer
Frontier shows one solid point tagged frontier. Neither is a defect; pick the reviewer for the
Pareto-line step or seed data that has two solid routes.

**C10. Tokens used.** The views use `--count` (ring, marks, whiskers), `--accent` (Pareto line,
focus), `--red`, `--green`, `--amber`, `--border-soft` and the `--neu-*` family, all defined or
derived for every palette and mode.
