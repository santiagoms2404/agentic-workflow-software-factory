## Handoff

### 2026-09-28 — from T01 and T02 (delivered manually; see the plan's 2026-09-28 Amendment)

**C1. Execution is manual now.** Use your prompt's `Manual:` lanes. T01 and T02 reached canonical
main through `1d5d494`; run `npm run test:unit` at your base first and record the count (2292 at
`1d5d494`). Commit only with the owner's authorization, as the owner, with no trailer.

**C2. Where the override plugs in.** `buildRoleRows` in `core/src/metrics/role-rows.ts` computes
`heuristicAttribution(run)` once per run and passes it to `roleRow`, which derives `blockedHere`
from it. A comment marks the spot. Your owner override replaces that value per run.
`RoleRow` has no `attribution`, `attributionSource` or heuristic field yet; task 3 adds all three.

**C3. `failedHere` reaches through host phases.** When a host phase (`kind` not `agent`) blocks the
run, `blockedAgentPhase` lands the block on the nearest earlier agent phase, so `t01-tests`
failing counts against `t01-build`'s role. Your journey's blocked runs should expect this.

**C4. Test fixtures.** `core/test/unit/_metrics-journal.ts` (`SyntheticAttempt`) builds synthetic
journals with phases, starts, route events, usage, calls, envelopes, gates and transitions, and
projects them through the projector. `metrics-phase-route.test.ts` already has a
rebuild-from-nothing harness through `Journal` that you can extend for the journey.

**C5. Two known semantics gaps, not yours to fix unless the journey trips on them.** One route can
appear under two keys: `route_model` is `opus` on journal rows and `claude:opus` on config rows,
and `route_provider` is NULL on config-derived Claude rows. A builder whose host tests phase
blocked the run is both `firstPass` and `blockedHere`. Both are carried to T04.
