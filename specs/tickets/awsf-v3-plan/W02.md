## Handoff

### 2026-10-05 — Returned W01 M1 cause-ledger findings

- **C1 — Trap-readout extension point.** The pure `summarizeCauses` in `core/src/metrics/causes.ts` consumes projected `MetricsRun[]` and their `run.attribution`. The payload's `causes.withoutCause` identifies project, task, attempt and lifecycle state; use those projected facts when designing the “stop without a trap” readout. W01 M1 did not add a trap field, trap layer, migration or new schema id.
- **C2 — Scope must be explicit.** The API/CLI JSON cause ledger includes all projected runs, including proving-ground replays; default text counts production with the existing source and started-before scope. The independent M1 review accepted this as a low-severity limitation. Define the trap catalogue's measurement population explicitly rather than treating JSON and default-text totals as interchangeable. Sources: `core/src/metrics/payload.ts`, `core/src/cli/commands/metrics.ts`, `core/test/unit/metrics-causes.test.ts`.
- **C3 — Cause precedence and legacy gaps.** Owner attribution overrides a BLOCKED heuristic. CANCELLED has no heuristic; a missing record or a recorded `unknown`, including an owner-recorded `unknown`, remains without a cause. Old stops and cancels were not backfilled by M1, so a missing-cause entry is not itself evidence of a new regression. Sources: `core/src/metrics/attribution.ts`, `core/src/metrics/causes.ts`.
- **C4 — Stub cancellation and owner boundary.** `awsf cancel` requires both cause and reason before prompting or signalling. Replace the placeholders in suggested prove cancel commands with real fixture values. Protected driving-document examples still require owner-side updates. W01 M1 is delivered, not the whole W01 workstream; this handoff changes no W02 state, prerequisite, prompt or owner gate.

### 2026-10-06 — Returned W01 M4 (K1) findings

- **C5 — The baseline worktree.** `awsf preflight` keeps one tree per project at `<worktree-root>/awsf-baseline-<project>` (`baselineWorktreeName` in `core/src/preflight/baseline-worktree.ts`). `awsf doctor` could report whether it exists, its HEAD against the base, and whether it is dirty or foreign. Seed paths already present there are never refreshed, because nothing may delete them, so a stale `node_modules` can mis-measure the base: a trap candidate.
- **C6 — Refusal texts to trap.** Each K1 field's refusal reasons are fixed strings in `core/src/preflight/fields.ts` (for example "is protected by <glob> and unclassified", "reads mode 0777, the signature of a DrvFs-mounted drive", "--consulted lacks"). The baseline refusals are "the baseline worktree was refused, and no gate ran", "gate <id> left it dirty in the baseline worktree" and `BaselineWorktreeForeign`. A scripted `awsf confirm` must hit `ConfirmNotInteractive` before any read (`core/src/cli/commands/confirm.ts`).

### 2026-10-07 — Returned W01 closing findings

- **C7 — K1 journeys to adopt as traps.** `core/test/journeys/k1-driver-checks.test.ts` holds one journey per K1 field, named `K1 <field id>: …` (suite, write-boundary, protected-paths, git-storage, duplicate, request-shape, prior-attempts, confirmation), and four stale journeys. A stale refusal carries `field: null` and refusal `stale-base`, `stale-config` or `stale-request`; paths edited after confirmation refuse as field `confirmation`. `prepareK1` and `startUnderK1` in `core/test/fixtures/k1-preflight.ts` reach a confirmed DRAFT before one fact is broken. The `awsf start --stub true` bypass is closed and each K1 journey proves it, so it is not a trap.
- **C8 — Trap candidates outside K1.** #11 and #17 (`isAvailable()` never resolves the executable, `core/src/adapters/claude-code.ts`), #14 (route-and-request rule), #18 and #22 (quota moves between start and run), #27's remainder (tickets demanding a path a shift cannot write), the stale baseline `node_modules` (seed paths are never refreshed), `awsf next`'s generic advice when a phase's one grant misses a planned path, a later phase's grant accepted at PREPARED (`grant.ts`), a `retry --adopt-as` target bypassing K1, an interrupted adoption left GATING with no host, and `duplicate` keying on the plan stem. A trap catalogue must state its population: the JSON cause ledger includes proving-ground replays.
