**C1. The journey your DONE WHEN names already exists and is green.**
`core/test/journeys/shift-ceiling.test.ts` (T09) walks a three-ticket shift into a ceiling pause and back
out through a raise and a resume, and asserts the ledger's `history()`. Re-run it as your check. Do not

**C2. M3 is `[wip]`, and the base T09 started from was red.** T08 set its ticket to `done` and left M3 at
`[]`. The sync fence refuses that pairing, so `npm run test:unit` was 2180/2181 at `852b0a8`. T09 set M3 to
`[wip]`. Your closing commit flips it to `[x]`.

**C3. The code wins over task 10's prose about the stop: it is before the build, not mid-phase.** A shift
cannot overspend on its first run, because admission and `coldCorrectionHeadroom` prevent it. What the
ceiling removes is a ticket's correction round. The shift now stops `RUNNING` under a `ceiling-pause`
checkpoint at the boundary before a cold, correcting ticket build it cannot fund with one correction to
spare. Stopping after a failed build was rejected: resuming it would need a path that discards the reply's
uncommitted writes, and the host has none. Do not add one.

**C4. The induced-import proof can use the new `core/src/workflow/shift/bind.ts`.** It sits under the fenced
directory and does file I/O, so it is the most plausible file for a real `raise.ts` import to land in.

**C5. Known gap, named and not fixed: the review is not covered by the pause.** The review launches at
`GATING`, where no checkpoint of this kind exists. If the last ticket's build spends the final call of
headroom on its correction, a cold reviewer runs without its correction round, as every shipped recipe's
reviewer does today.
