### 2026-09-25 — from T04

**C1. The compiler's entry point.** `core/src/workflow/shift/compile.ts` exports
`compileShift(manifest, bodies, config)` → `ShiftRecipe` (`{ id: "shift", tier, manifestDigest, phases }`)
and `SHIFT_WORKFLOW_ID = "shift"`. `bodies` is a `ReadonlyMap<ticketId, Uint8Array>` of whole ticket
files, and `config` is `{ prompts: { builder, reviewer } }`. The compiler reads nothing, so every caller
you give a compiled path must read the ticket files and call `loadUserPrompt` itself. Build
`COMPILED_WORKFLOW_IDS` from `SHIFT_WORKFLOW_ID` rather than retyping the string.

**C2. FINDING: a real shift does not compile through `compileWorkflow` yet.** For N >= 2,
`compileWorkflowStructure` throws `InvalidReviewBuildProducerCount` until T06 lands. A T05 path that
compiles a shift end to end must either run after T06 or test with a one-ticket manifest.

**C3. The tier is decided.** `SHIFT_TIER_FLOOR = 2`, raised by any tier a ticket declares and never
lowered by one. This answers T02's C7. Do not re-derive it in the catalogue.
