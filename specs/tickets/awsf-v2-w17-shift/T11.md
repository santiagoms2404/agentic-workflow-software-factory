**C1. SCOPE added to this task: two runner gaps a shift hits first here.** The plan's task 11 now has
two new rows. (a) `production-run.ts`'s `engineer` branch must emit a shift brief's compiled `intent`
(`ShiftBriefPhase.intent` from `core/src/workflow/shift/compile.ts`) instead of `requestOutput(status)`.
Today every `t<NN>-brief` would carry the attempt's request. (b) `shift-review-context` must compose
every `t<NN>-brief`'s intent. Today review intent is `schemas.get("awsf.plan-output/v1")`, and last wins.
The plan wins over this ticket's prompt, which predates the finding.

**C2. Do not "fix" `{previous_envelope}`.** Ticket n's builder is rendered its own brief. Ticket n-1's
build envelope is only in the schema map. The plan's 2026-09-25 amendment records this as intended.

### 2026-09-25 — from T07, carrying forward T05's C3

**C3. FINDING: no task in this plan binds a sealed selection to an attempt.** `awsf start` on a shift
throws `CompiledWorkflowUnbound` (`core/src/workflow/catalog.ts`) because `AttemptStatus` has no field
for a sealed manifest — T05 built the refusal, not the binding, and named T11/T12 as the first tickets
that would need it. This task is the first to run a shift through `production-run.ts` (per its own
GATE G17-M and READ FIRST block), so it is the one that must: add the manifest-binding field to
`AttemptStatus`, and replace `CompiledWorkflowUnbound` with a real call to `compiledWorkflow("shift").compile`
once a manifest is bound. If T12 reaches this gap first instead, this finding applies there unchanged —
whichever of T11/T12 starts first owns the binding, and the other inherits it done.
