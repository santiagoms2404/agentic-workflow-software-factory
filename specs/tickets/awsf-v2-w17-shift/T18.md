### 2026-09-25 — from T09 (T18 does not depend on T09; this is here because the gap has no other owner)

**C1. A real terminal cannot start a shift yet, and no remaining ticket builds that. Your live drive needs
it.** The plan's New Files row says `awsf shift plan` also writes the manifest. T08 built only the
arithmetic, and `a66ccde` wired the readout into `main.ts` without writing anything. T09 bound a sealed
manifest to an attempt (`AttemptStatus.shift`, set by `newCommand({ shift })`), but no CLI flag passes one
to `awsf new`. Every journey so far calls `newCommand` directly. Before the bounded live drive, something
must seal the selection (`selectShiftTickets` → `sealShiftManifest` with `ticketFileDigest` per ticket) and
hand it to `awsf new --workflow shift`. Q5 decided the manifest lives in the state root beside the attempt,
and the binding already stores it on the attempt's status. So the missing piece is the CLI path, not a new
record. If an earlier ticket builds it first, it should say so here. Otherwise it is yours, and the plan
wins over your prompt on this point, because the prompt predates the finding.
