### 2026-09-25 — from T04

**C1. SCOPE already green from T04.** `shift-compile.test.ts` (11 tests) covers phase shape,
ordering, `minimumCalls === N + 1`, earned descriptions, the `reducePhaseContext` chain and refusals.
The cross-process reproducibility check is done too: `core/test/unit/_shift-compile-child.ts` compiles
in a fresh `node` process and the test compares its `serializeShiftRecipe` output byte for byte. T07
still owns the induced-violation proofs for T05's and T06's rules.

**C2. CONTRADICTION: the plan's task 4 wording on `{previous_envelope}` is wrong, and the code wins.**
The plan says ticket n's builder receives ticket n-1's build envelope as `{previous_envelope}`.
`reducePhaseContext` returns `previous` = the last accepted envelope, which is ticket n's own
`t<NN>-brief`. Ticket n-1's build envelope is only `schemas.get("awsf.build-output/v1")` (last wins,
asserted). The test asserts the real behaviour, including that "built t02" is absent from t03's
rendered builder prompt. This is the right behaviour: the builder needs its own ticket's prompt, and
n-1's work is already in the tree. Do not reorder phases to make the plan's sentence true.

**C3. FINDING for the first ticket that runs a shift through `production-run.ts` (M4/M5).** Two
runner behaviours defeat the brief as it stands:
(a) the `engineer` branch ignores `phase.execute` and emits `requestOutput(status)`, so a brief would
carry the attempt's request instead of its ticket's prompt. A shift brief must emit its phase's
`intent` (`ShiftBriefPhase.intent`, already built at compile time).
(b) review `intent` is `schemas.get("awsf.plan-output/v1")`, and last wins, so `shift-review-context`
would see only the last ticket's brief. It needs every `t<NN>-brief`.
Neither is in M2's scope. Carry both forward to T11 or T14's Handoff when M2 closes.
