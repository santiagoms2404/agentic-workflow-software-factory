**C2. Absorb: the two-process direction of the digest property is not proved yet.**
`core/test/unit/shift-selection-record.test.ts` proves one changed byte in each of three tickets changes
`manifestDigest` and that restoring the byte restores it, in one process. The cross-process

`two-blocks.md` back the body reader's refusals. Their names avoid `T\d\d.md`, so no tickets-root
scan reads them as a ticket set; keep that true for any fixture ticket directory you add.

**C4. Markers: the fence overrules the README on milestone headers.** The ticket/plan-sync fence
refuses a `done` ticket under a `[]` milestone (`ticket state agrees with its milestone's marker`), so
T01 flipped M1's `<h3>` to `[wip]`. The README says a milestone header moves only on its last task.
The fence (code) wins: M1 is `[wip]` now; your commit flips it to `[x]`.

**C5. RENAMED: no tracked file may carry `manifest` in its name.** AGENTS.md invariant 10's
junk-drawer fence (`core/test/unit/meta/junk-drawer.test.ts`) refuses every `git ls-files` basename
matching `/manifest/i` or `/receipt/i`. The plan's `shift-manifest.ts` and `shift-manifest.test.ts`
were therefore committed as `core/src/contracts/shift-selection-record.ts` and
`core/test/unit/shift-selection-record.test.ts`. The schema id `awsf.shift-manifest/v1`, the
`ShiftManifestSchema` export and the `manifestDigest` field keep their names; only file names are
fenced. AGENTS.md wins over the plan and the prompt. The fence reads tracked files only, so an
untracked `*manifest*` file passes a pre-commit suite and fails the first run after the commit.
Your DONE WHEN row `shift-manifest.test.ts` means `shift-selection-record.test.ts`.
