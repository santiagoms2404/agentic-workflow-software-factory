## What this ticket is

The **testing and closing** ticket for M1. It proves the decision service end to end on stubs, adds what awsf doctor reports about Jev, and supplies M1's Amendment evidence.

The shared conventions (what Jev is, execution, the write boundary, the owner gates, the
never-do list) are in [`./README.md`](./README.md) and Section A of the build prompts, and apply
unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there after delivery, from the findings earlier tickets return. It sits above the
prompt because the sync fence compares everything after the prompt heading with Section B byte
for byte.

## Handoff

### 2026-09-29 — from T01 (delivered as `ed7e71c`, `6b1751d`, `56a8101`)

**C1. The doctor row's parts, without a network call.** Switch: `jevSwitchOf(catalog)`
(`core/src/registry/catalog-schema.ts`, `on` when the catalog is silent). Key: whether
`process.env.OPENROUTER_API_KEY?.trim()` is non-empty. `JevTransport.available` is true only when
both the switch is on *and* the key is set, so don't use it for the key alone. Requested model:
`JEV_DEFAULT_MODEL`. The transport has no getter for a pinned model; add one if the row must show
a pin.

**C2. Fence status: don't spell the endpoint.** The fence
(`core/test/unit/meta/jev-transport-fence.test.ts`) fails any `core/src` file other than the
transport that matches `/api\/alpha\/decisions/` or a bare or `globalThis` fetch. If the doctor
scans `core/src` itself, import `JEV_ENDPOINT` from the transport, and write any pattern as a
regex with escaped slashes: the fence's own regex sources don't match themselves, but a plain
string holding the path does.

**C3. Stub at `fetch`, or at the port.** `core/test/unit/decision/jev-transport.test.ts` stubs
with `t.mock.method(globalThis, "fetch", …)`. The journey can do the same, or hand `decide()` a
fake `ask` port (T02 C3). The fence covers only `core/src`, so test files are free to stub.

**C4. Unit counts.** At `ebd85d9` Windows node reports 2383 tests, 124 failing: POSIX-only tests
(file modes, symlinks, shell). The same 124 fail after T01, which adds 29 tests (2383 → 2412,
2255 → 2284 pass). Record the counts from WSL, where the suite is expected to be green.

### 2026-09-29 — from T02 (delivered as `07e43d8`, `3417e81`, `6d85dba`, `0371f2d`)

**C1. The journey drives `decide()` through its port.** `decide(questionSet, state, context)` in
`core/src/decision/decide.ts` takes `context.transport: Pick<JevTransport, "ask">`, plus
`taskRoot`, `project`, `taskId`, `attempt` (a number, or null for a task-level call), `caller`
(`{ kind: "stop" | "phase-hook" | "tool" | "replay", name }`), `params`, and optional `model`,
`signal`, `projectDecision`, `now`, `newId`. It returns `{ outcome, answers, policyResult,
recordId, record }`. `core/test/unit/decision/decide.test.ts` already stubs the port for every
outcome. Hand the journey a real `JevTransport` with fetch stubbed if it has to prove the whole
chain.

**C2. Live rows need `projectDecision`.** `decide()` writes `decisions.jsonl` whatever happens,
but it projects only through `context.projectDecision`. Pass
`createDashboardProjection(stateRoot).projectDecision` to get the `decision` events row live;
`awsf db rebuild` places it otherwise. A row lands on the session of the attempt the record names
(a task-level record goes on the newest attempt), so the task needs a projected session first.

**C3. Unit counts.** At `91dc117` WSL reports 2463/2463. T02 adds 13 tests, so start from 2476.
The full suite took about 20 minutes on a loaded machine. Keep a `wsl.exe` client attached for
the whole run, because a detached run dies.
