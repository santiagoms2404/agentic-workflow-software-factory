## What this ticket is

An **implementation** ticket. Every question AWSF asks Jev becomes a named, versioned question set with its thresholds and pure policy in one file, and every call leaves one journaled decision record.

The shared conventions (what Jev is, execution, the write boundary, the owner gates, the
never-do list) are in [`./README.md`](./README.md) and Section A of the build prompts, and apply
unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there after delivery, from the findings earlier tickets return. It sits above the
prompt because the sync fence compares everything after the prompt heading with Section B byte
for byte.

## Handoff

### 2026-09-29 — from T01 (delivered as `ed7e71c`, `6b1751d`, `56a8101`)

**C1. The transport's outcomes are the record's outcomes.** `JevTransport.ask()` in
`core/src/decision/jev-transport.ts` returns `JevOutcome`, a union on `outcome`: `answered`,
`contract-error`, `unavailable` (with `reason`: `missing-key`, `http-status`,
`retries-exhausted`, `network`, `redirect`, `timeout`, `aborted`) or `refused-by-switch`. Every
outcome except `refused-by-switch` carries `requestedModel`, `elapsedMs`, `attempts`,
`redacted` and `requestText`. `answered` adds `answers`, `usage`, `resolvedModel`, `cost` and
`responseText`; `contract-error` adds `error` and `responseText`. `refused-by-switch` carries
only `detail`: nothing was built, so take the requested model from the context (the default is
`JEV_DEFAULT_MODEL`) and record `redacted: false`.

**C2. One contradiction: an invalid request throws.** A request that could never be valid (an
empty choice, 1 or 11 score levels, blank instructions) throws `QuestionValidationError` before
anything is sent, instead of returning an outcome. This prompt's outcome list has no
`invalid-request`, and a malformed question set is a code defect, not a runtime condition, so the
throw wins. Call `validateJevQuestions` when a set is registered, so a bad static set never
reaches `ask()`. `next_act`'s options are built per stop, so always include `wait_for_owner` and
`other`, and the choice can never be empty.

**C3. Take the transport as a port; don't build it inside `decide()`.** Pass
`Pick<JevTransport, "ask">` in the context. T03's journey can then stub it, and the host builds
one `JevTransport` per process (the key is read once, at construction). `projectSwitch` is a
required constructor option on purpose: get it from `jevSwitchOf(catalog)` in
`core/src/registry/catalog-schema.ts`.

**C4. `responseText` is the provider's raw text and is not redacted.** `requestText` is the
redacted wire body. Pass `responseText` through `scrubJsonText` (`core/src/policy/redaction.ts`)
before it enters a record, and apply the 16 KiB rule to the scrubbed bodies.

**C5. An unknown cost is `{ amount: null, source: "unknown" }`.** Keep the null in the record;
never coerce it to 0. `resolvedModel` exists only on `answered`, so leave it absent otherwise
rather than copying the requested alias into it.
