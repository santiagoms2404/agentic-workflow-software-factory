## Handoff

### 2026-09-29 — from T07 (delivered as `34c5c1b`)

**C1. Agreement is not in SQLite.** The prompt reads "agreement per act (from task 6)" through
read-only SQL, but no proposal, replay or pair is projected. Live proposals are in each task's
`delegate.jsonl`, replays are in `<state-root>/delegate/replays.jsonl`, and pairs are computed at
read time by `readLivePairs` and `readReplayPairs` (`core/src/delegate/pairs.ts`). Only T02's
`decision` records reach SQLite, as `events` rows on rebuild. Either compute agreement in the API
layer from those readers, or add a projection through `projector.ts` and `rebuild.ts` (the only
SQLite writer, invariant 6). Don't add a second store. T06's "no running tally" rules out
caching the pairs.

**C2. Label replay rows by source and mode.** A replay pair has `source: "replay"`, and its
record has `mode: "numbers-only" | "live"`. `effectiveReplays` keeps one record per stop and
prefers live. Numbers-only replays asked Jev nothing, so they carry no resolved model or
question-set version (`decision.outcome: "numbers-only"`, `recordId: null`). Q7's "every row
carries the resolved Jev model" can only be met for live pairs. Label the numbers-only rows as
such rather than leaving the model blank.

**C3. Live replay decisions are outside the task roots.** A `--live` replay journals its
stop-judgment calls to `<state-root>/delegate/decisions.jsonl` (caller kind `replay`), not to a
task's `decisions.jsonl`. `awsf db rebuild` doesn't read that file today, so Jev spend by cost
source misses replay calls unless T26 reads it too.
