## What this ticket is

An **implementation** ticket. Agent phases reach Jev only through the host, so the key never enters an agent's environment and every call is journaled in one place.

The shared conventions (what Jev is, execution, the write boundary, the owner gates, the
never-do list) are in [`./README.md`](./README.md) and Section A of the build prompts, and apply
unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there after delivery, from the findings earlier tickets return. It sits above the
prompt because the sync fence compares everything after the prompt heading with Section B byte
for byte.

## Handoff

### 2026-09-29 — from T02 (delivered as `07e43d8`, `3417e81`, `6d85dba`, `0371f2d`)

**C1. The socket answers through `decide()`.** Every question a phase asks is a registered set
(`QuestionSetRegistry` in `core/src/decision/question-set.ts`, refusing a duplicate
`id@version`). Look the set up by id and version, then call `decide()` with
`caller: { kind: "phase-hook" | "tool", name }`. Don't let a phase send free-form questions:
the set's `questions(params)` builds them, and registering a set validates it.

**C2. `questions` is a function of the call's parameters.** A `QuestionSet` has
`questions(params)` and a `sampleParams` the registry validates at registration. A static set
ignores `params`, and a per-call set (`stop-judgment`'s `next_act`) uses them. Validate what a
phase supplies as `params` at the socket before building questions from it.

**C3. What goes back to the phase.** Return the typed `answers` and `policyResult`, never
`record.bodies`. The bodies are redacted, but they are the audit trail, not a phase input.
