## What this ticket is

The **testing and closing** ticket for M2. It adds the replay that seeds the shadow record from the owner's past stops, and supplies M2's Amendment evidence.

The shared conventions (what Jev is, execution, the write boundary, the owner gates, the
never-do list) are in [`./README.md`](./README.md) and Section A of the build prompts, and apply
unchanged.

The `## Handoff` section below is empty at authoring. The owner appends dated, numbered entries
(C1, C2, …) there after delivery, from the findings earlier tickets return. It sits above the
prompt because the sync fence compares everything after the prompt heading with Section B byte
for byte.

## Handoff

### 2026-09-29 — from T03 (delivered as `5915c87`, `1ac91ae`)

**C1. Decision tests live in a folder, not behind a prefix.** M1's check command
`core/test/unit/decision-*.test.ts` matches no file. Since T01 the tests have lived in
`core/test/unit/decision/*.test.ts`, and that is the path that was run and recorded. If this
ticket's checks name a glob for new tests, use the folder form (`core/test/unit/delegate/*.test.ts`
or whatever the files really are) and run it once to confirm it matches.

**C2. The journey to copy.** `core/test/journeys/decision-service.test.ts` drives `decide()`
through a real `JevTransport` with only global fetch stubbed (`t.mock.method(globalThis,
"fetch", …)`), in a scratch repository with its own `awsf.project.yaml`. It rebuilds through
`main({ argv: ["db", "rebuild", "--state-root", …] })` after deleting `awsf.db` and its `-wal`
and `-shm` files. A replay journey can use the same shape: a stubbed fetch per stop for
`--live`, and none at all for the numbers-only path.

**C3. Adding to `awsf doctor`.** `doctorCommand(stateRoot)` must keep exactly one argument, a
state root: `core/test/unit/registry/state-root-containment.test.ts` pins both its arity and its
signature text. Add a row the way the Jev row does it: a separate builder
(`jevDoctorRow` in `core/src/decision/jev-doctor.ts`) merged by `withJevRow` in
`core/src/cli/commands/doctor.ts`, composed in `main.ts`.

**C4. Unit counts and timing.** At `1ac91ae` WSL reports 2481/2481. The journey file isn't in
`test:unit`; it runs under `test:journeys`. A full unit run took 15–20 minutes on a loaded
machine. Launch it from a hidden `wsl.exe` that stays attached, then poll the TAP file.

### 2026-09-29 — from T05 (delivered as `364f15d`)

**C5. "Numbers-only" is not a mode the policy has yet.** `proposeAct` in
`core/src/delegate/policy.ts` treats a missing answer as the plan's unavailable case. Every act
that needs judgment, including a ceiling-pause's raise, becomes wait-for-owner with
`jev-unavailable`. Passing `{ outcome: "unavailable", result: null }` for a replay without
`--live` would therefore propose raise nowhere. Add an explicit numbers-only judgment input,
where the code-decided rows stand and the judgment rows wait, and table-test it. Don't
reinterpret "unavailable". The plan's rule that an unavailable decision records wait-for-owner
applies to live stops and still wins there.

**C6. Rebuilding historical facts.** Every attempt-journal record's `event.next` is the status
at that point, so `buildStopFacts(records[i].event.next, records.slice(0, i + 1), config)`
reproduces the facts at any stop. `stopFactsPhases(options, status)` in `production-run.ts`
supplies `config` and the roles, but it resolves routes against today's config. A route that no
longer resolves comes back as `null`, which the raise arithmetic counts as a host-only phase.

**C7. Test paths.** M2's check row names `core/test/unit/delegate-*.test.ts`, which matches
nothing. The tests are in `core/test/unit/delegate/*.test.ts` (stop-facts, policy, shadow). At
`364f15d` WSL reports test:unit 2526/2526, test:sim 98/98 and test:contract 149/149. The
production-runner and decision-service journeys pass 105/105.

**C8. `awsf run` now writes two task files.** In a journey, each stop reached through `awsf run`,
`resume` or `intake` appends to `decisions.jsonl` (an unavailable decision, because the key is
withheld under the test runner) and to `delegate.jsonl` in the task root. `awsf db rebuild`
projects those decisions as `decision` event rows, so a journey that counts events after a
rebuild will see them.
